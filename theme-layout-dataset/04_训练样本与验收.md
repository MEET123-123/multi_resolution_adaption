# 从标注到多模态微调

以下是训练任务与验收合同，先用于指导标注。完整组件树/关系任务的导出器与执行器接入需在试标后实现；现有根组接口可先承接其中不改变拓扑的布局子集。

## 1. 四类任务分开导出

| 任务 | 模型实际输入 | 监督答案 | 训练目的 |
|---|---|---|---|
| A 源结构理解 | 源整屏图、节点候选/局部视觉证据；不含人工正确分组 | 语义组件树、成员绑定、关键观察关系 | 学会哪些对象构成一个布局单元 |
| B 全局布局 | 源图、源组件摘要、目标画布与事前 brief | 布局模式、关键目标关系、目标根组框；可分为规划与几何两个子任务 | 学会保留哪些关系、在哪些区域重排 |
| C 局部重排 | 整屏上下文、父组范围、局部图、子组件条件 | 组内顺序、行列/网格和子框 | 处理复杂容器，减少全局输出长度 |
| D 问题修正 | 当前候选渲染、源参考、需求、可编辑组 | 问题对象、规则、修复动作或修正框 | 学会定位并修正布局缺陷 |

候选偏好 A/B 另存评价数据；后续是否用于偏好优化，取决于偏好数量、一致性与训练框架，不与主任务 SFT 混为一种答案。

**两种部署条件要提前选定**：如果 B 使用人工确认的源组件作条件，推理时也需要可用的组件提供器；这只能证明“给定组件时”的布局能力。若希望端到端从图像适配，需要部署 A 或可靠的自动分组模块，并同时报告使用预测组件时的 B 效果，不能只报告人工组件条件下的成绩。

## 2. 训练输入只用白名单

给 B 的最小输入包含源图、源组件 ID/角色/源框/容器策略、必要的源关系、目标画布/安全区和事前 brief。底层成员与完整脚本留在证据库，不直接铺进每条提示。

以下内容不得进入 B 的用户输入：

- 目标参考图、最终目标框、最终改后图。
- 由目标答案反推出来但推理时拿不到的关系、留白或设计描述。
- 标注者、审核结果、测试集合标签、目标文件名中的答案线索。
- 将算法候选自身作为答案时，完全相同的候选坐标。

源布局恰好与目标正确布局相同是合法情况；要检查的是字段生成来源，而不是看到坐标相等就判泄漏。

允许给“明确的目标关系需求”，但必须证明它是事前 brief，并且部署时可得到。如果先从人工目标布局抽关系再喂给模型，任务应命名为“给定关系的布局生成”，不能冒称模型独立发现了设计意图。

纠错任务 D 可以输入当前候选图/框，因为它的任务就是修改候选；最终修正答案仍只能在助手监督里。

## 3. 不把粗到细变成隐藏答案提示

分步结构可以是：先生成组件/关系计划，再生成根组几何，最后按需生成局部几何。每一步都要定义部署时可用的输入。

- 训练规划模块时不把正确计划放进输入。
- 训练几何模块时可用正确计划作条件，但评估时需同时测“人工计划”和“模型预测计划”，识别误差传播。
- 有限、可观察的设计说明可作监督；不要求标注者编造冗长的思维过程。
- 序列超过预算时拆任务或简化证据，不截断答案、不静默丢弃尾部组件。
- 全局/局部任务共享同一主题家族拆分，局部任务不能泄漏到另一个集合。

## 4. 与当前项目对接

当前 `multires-layout/1` 助手输出为：`{"schema":"multires-layout/1","groups":{"<组ID>":[x,y,w,h]}}`，相对目标安全区归一化到 1000。

只把“既定组身份不变、组内比例可由统一缩放实现”的 B 子集映射到该接口。当前求解器会投影模型框，可能改变最终坐标，所以原始提案与执行后结果必须分别评分。

新规范的关系/模式字段不能直接塞进上述答案 JSON：当前校验器会拒绝额外字段。要训练这些能力，需单独版本化规划输出或建立独立任务导出器，并实现消费它的执行链路。

现有浏览器标注页可用于检查固定组框；组件树、关系、批量排除、双标仲裁先用本工作区 JSON/CSV，试标稳定后再把界面扩展为完整工具。本轮 `annotation_tasks.py` 提供空表单及检查，不提供尚未实现的训练导出能力。

后续导出应重建输入白名单，输出 `train/validation/test.jsonl`、样本到家族映射、图像哈希、标注版本和排除理由。不要直接把整个 annotation JSON 塞进模型用户消息。

## 5. 设计数据组成

首批先让每类关键变化都有覆盖：保持原布局、位置调整、主体避让、竖向堆叠变横向/多区、容器重排、设置面板、局部修正。有意保留少量正确无需修改的样本，避免模型学成“见到输入就必须改动”。

不要用时间变化、换色、连续帧凑数量；同一个简单模板的多个方案/裁剪会增加记录数，却不会增加独立主题家族数。统计家族数、独立状态数、目标画布数、设计模式覆盖与样本数。

待真实标注跑通后再制定任务混合比例、图像分辨率、token 预算和 LoRA 参数，不先声称某个比例/训练步数通用有效。

## 6. 怎样判断模型学到了布局

固定同一测试家族，比较：直接等比缩放、现有 anchor 算法、未微调模型、微调模型；微调模型同时报告原始输出和约束后的输出。

| 维度 | 要报告什么 |
|---|---|
| 结构 | 组件覆盖、成员分组 F1、层级错误、关键角色遗漏 |
| 几何 | JSON 合法率、ID 完整率、越界、间距/对齐约束违反率；仅对匹配方案计算框 MAE/IoU |
| 关系/响应式 | 关键关系满足率、布局模式、各画布表现、同主题跨状态一致性 |
| 内容 | 主体误遮挡、文字可读性、允许叠层例外是否保留 |
| 执行 | 提案应用率、约束投影幅度、XML 写回、交互热区和状态回放、真机验证状态 |
| 设计 | 同源素材与同 brief 的盲评、可接受率、两方案偏好及分歧 |
| 泛化 | 完全未见家族、不同脚本结构/素材风格；各类失败分布 |

只以框误差评估会惩罚另一种合理布局；只以盲评又无法保证可执行。两者都保留，硬约束违规优先处理。

建议增加消融：删除关系条件、删除背景图、用自动/预测分组替代人工分组，观察指标变化。若去掉图像效果几乎不变，需检查任务是否主要靠模板/坐标就能回答；若只改善 JSON 合法率，不能宣称已学会设计重排。

没有人工独立测试标签时，可以验证链路和约束，不能量化真实布局学习收益；teacher replay、合成修复或训练 loss 下降也不能代替这一证据。
