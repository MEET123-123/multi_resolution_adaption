# 主题布局数据集：先定规范，再人工标注

本工作区面向**鸿蒙锁屏主题从源设备到目标画布的布局适配**，服务后续多模态模型微调。包含人工标注规范与自动构建两条工作路径。

**本地微调已完成**：RTX 4060 8GB / Qwen3-VL-2B / 4 位 QLoRA，140 条训练样本完整一轮。验证损失下降 7.36%，但固定 6 条测试子集的坐标 MAE 从 97.26 升至 119.32，尚未证明布局质量改善。适配器、原始预测和完整报告见 [本地微调结果](06_本地微调结果.md)。

**2026-10-23：已按要求使用现有主题生成可迁移到服务器的算法监督数据。** 共处理 24 个源包、25 份缓存，424 对候选中保留 219 对（训练 140 / 验证 24 / 测试 55），覆盖 13 个家族、76 个源状态。数据、图片、证据、训练/评估脚本位于 `runs/auto-pairs-v1/server-bundle/`。见 [自动构建结果与服务器使用](05_自动构建与服务器使用.md)。算法生成记录保留 weak 来源，不冒充人工标注。

建议按顺序阅读：

1. [调研与设计依据](01_调研与设计依据.md)：参考了哪些 UI / 自动排版研究，哪些做法适合迁移。
2. [标注规范 v1](02_标注规范_v1.md)：标什么、以什么粒度标、什么情况挂起。
3. [人工标注流程](03_人工标注流程.md)：从选样、试标到复核和冻结，逐步操作与验收。
4. [训练样本与验收](04_训练样本与验收.md)：怎样把标签变成训练任务，怎样验证学到了布局。

核心单元是**场景 → 语义组件 → 必要的局部子组件**。底层 XML 节点、序列帧、装饰碎片自动归档为证据，不要求人工逐个重画框，也不将完整节点列表平铺为每条训练答案。组件数量不是越少越好：两个需要独立移动的对象必须可分开；一个时间组内的四个数字不应无理由拆成四个全局任务。

```text
theme-layout-dataset/
├─ 01_调研与设计依据.md
├─ 02_标注规范_v1.md
├─ 03_人工标注流程.md
├─ 04_训练样本与验收.md
├─ templates/                空白任务、排班与质检表
├─ config/                   角色/关系词表
├─ annotation_tasks.py       创建空白任务、检查草稿/发布条件
├─ build_training_pairs.py   真实主题配对、质量筛选、打包和评估
├─ preflight_tokens.py       CPU 上检查实际图文输入与答案掩码
├─ incoming/                 新增来源包
├─ registry/                 本地来源盘点
├─ annotations/              留给你人工填写的任务目录
└─ runs/                     解析缓存及以后运行的生成物，本地保留
```

从项目根目录执行，可创建待填写任务；不会生成组件类别、关系或目标框：

```powershell
.\.venv\Scripts\python.exe .\theme-layout-dataset\annotation_tasks.py init --id pilot-001
.\.venv\Scripts\python.exe .\theme-layout-dataset\annotation_tasks.py validate --task annotations/pilot-001.json
```

人工填写并复核后再检查发布条件：

```powershell
.\.venv\Scripts\python.exe .\theme-layout-dataset\annotation_tasks.py validate --task annotations/pilot-001.json --release
```

草稿允许留空；发布检查会拒绝未填写的来源、组件树、关系/约束审查、目标框、独立复核和验收结果。程序检查结构完整性，不能代替设计判断。

本地盘点为 24 个根目录 HWT。早期 `runs/pilot-v1/` 是未完成的解析试点，保留作历史记录；本次已改为校验并复用现有缓存，运行目录为 `runs/auto-pairs-v1/`，两者不要混用。

本次 SFT 使用现有 `multires-layout/1` 根组接口，输入仅保留源组件事实与目标画布条件；完整组件树留在证据中。人工规范中的任意拆组/换序任务仍需独立执行协议；现有固定根组标注页不能代表完整的新规范。
