# 主题布局数据集：先定规范，再人工标注

本工作区面向**鸿蒙锁屏主题从源设备到目标画布的布局适配**，服务后续多模态模型微调。当前交付的是调研、标注规范、人工操作流程、空白表单与检查工具；没有替你标注真实主题，也没有自动批准算法候选。

建议按顺序阅读：

1. [调研与设计依据](01_调研与设计依据.md)：参考了哪些 UI / 自动排版研究，哪些做法适合迁移。
2. [标注规范 v1](02_标注规范_v1.md)：标什么、以什么粒度标、什么情况挂起。
3. [人工标注流程](03_人工标注流程.md)：从选样、试标到复核和冻结，逐步操作与验收。
4. [训练样本与验收](04_训练样本与验收.md)：怎样把标签变成训练任务，怎样验证学到了布局。

核心单元是**场景 → 语义组件 → 必要的局部子组件**。底层 XML 节点、序列帧、装饰碎片自动归档为证据，不要求人工逐个重画框，也不将完整节点列表平铺为每条训练答案。组件数量不是越少越好：两个需要独立移动的对象必须可分开；一个时间组内的四个数字不应无理由拆成四个全局任务。

```text
theme-layout-dataset/
├─ 01_调研与设计依据.md
├─ 02_标注规范_v1.md
├─ 03_人工标注流程.md
├─ 04_训练样本与验收.md
├─ templates/                空白任务、排班与质检表
├─ config/                   角色/关系词表
├─ annotation_tasks.py       创建空白任务、检查草稿/发布条件
├─ incoming/                 新增来源包
├─ registry/                 本地来源盘点
├─ annotations/              留给你人工填写的任务目录
└─ runs/                     解析缓存及以后运行的生成物，本地保留
```

从项目根目录执行，可创建待填写任务；不会生成组件类别、关系或目标框：

```powershell
.\.venv\Scripts\python.exe .\theme-layout-dataset\annotation_tasks.py init --id pilot-001
.\.venv\Scripts\python.exe .\theme-layout-dataset\annotation_tasks.py validate --task annotations/pilot-001.json
```

人工填写并复核后再检查发布条件：

```powershell
.\.venv\Scripts\python.exe .\theme-layout-dataset\annotation_tasks.py validate --task annotations/pilot-001.json --release
```

草稿允许留空；发布检查会拒绝未填写的来源、组件树、关系/约束审查、目标框、独立复核和验收结果。程序检查结构完整性，不能代替设计判断。
