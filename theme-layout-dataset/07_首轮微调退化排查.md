# 首轮微调退化排查

本记录基于 `runs/local-qlora-v1/` 的真实输出和训练实现。没有重新训练，也没有依据测试子集反复调参。

## 已确认的现象

- 验证集 token 损失：1.408504 → 1.304877。
- 固定六条测试子集相对算法教师的 MAE：97.25894 → 119.32458，增加约 22.69%。
- 底座六条输出的 96 个坐标全部等于源组框，即复制源布局；这个分数并不证明底座完成了目标重排。
- 微调后仍有三条完整复制源框；另外三条发生变化，整体表现为一条改善、两条退化、三条不变。

净增误差主要来自小新竖屏，不能描述为六条样本全面变差。该样本 `g3` 的目标框为宽 738.462、高 1076.923；微调后宽高均输出 100。框值相对目标安全区归一化到 1000；该组含跨画布背景，目标高度大于 1000 并非单纯的非法数值。

## 训练实现和数据中的问题

1. **目标函数与布局指标不一致。** 训练、验证使用助手文本的 token 交叉熵；它没有直接度量 xywh 数值误差、比例、边界、间距和遮挡。验证还使用正确答案前缀，与自由生成的条件不同。因此损失下降不能推出最终坐标更准。该性质有一般研究依据，具体退化贡献仍需对照实验确认。

2. **选模标准缺少几何指标。** 当前程序按验证 token loss 选训练轮次，没有在验证集生成布局并计算几何指标；底座也没有作为可保留的候选。本次只有一轮和 35 次更新，未进行基于验证几何指标的配置比较。

3. **独立设计覆盖有限。** 140 条训练样本实际来自 9 个家族、49 个源状态，包含同状态的多个目标画布。不能把这些记录当作 140 个独立设计。所有目标均由同一算法教师产生，尚无独立设计师布局监督。

4. **分组与语义检查不充分。** 小新竖屏的 `g3` 输入只标作 `content`，其底层包含一张 1080×2520 的背景图及多个交互对象。它具有复杂的背景/控件排布含义，而输入缺乏明确的背景策略与内部布局说明。原始证据里还有“随小时变化的图片被推断为 clock.hour”的语义噪声；此元素级标签没有进入本次主 SFT 输入，不能声称它直接导致了本轮输出错误。主输入的粗分组和粗角色仍需审核。

本轮构建充分检查了渲染、几何与文件完整性，但这些检查不能代替语义分组审核。这是数据准备中需要补齐的一关。

## 目前不能确认的解释

- 不能仅凭一次实验就判断学习率过高、过拟合或量化是主因。
- 不能保证增加轮数或换更大模型能修复问题。
- 当前只有两个测试家族、六条自由生成结果，不能推断整个 55 条测试集或全部主题的表现。
- 语言 token loss 的下降与坐标退化可以同时存在；它们不是计算矛盾。

## 下一轮应优先改变的环节

1. 先修语义组件边界：背景变换、装饰、交互控件与局部容器分别有明确策略，避免一个泛化大组承担多种布局责任。
2. 补充“关系保留/变化、布局模式、局部重排”等监督；模型当前主要在复现数值坐标。
3. 在验证集执行真实生成，按坐标误差与布局约束共同选 checkpoint，并保留复制源框和原算法基线。
4. 对比关系/操作或坐标残差表示与直接绝对坐标输出；如引入数值距离相关损失，需独立实验，不直接假定有效。
5. 固定测试集，只在方案与参数确定后做最终对照。数据与目标定义稳定后再扩大训练规模。

相关一手研究：[Regress, Don't Guess（ICML 2025）](https://tum-ai.github.io/number-token-loss/)，讨论普通交叉熵缺乏数值距离信息，并提出数值 token 损失。本文只借其解释目标函数差异，不将其结果当作本任务已验证的改进。
