# 标注规范 v1

本规范适用于锁屏主题跨画布布局适配。优先标注**布局决策与可执行结果**。数值预算和质检阈值均为项目试点建议，需根据试标统计调整。

## 1. 一条任务是什么

任务键由以下信息确定：`主题版本 + 场景 + 样式 + 交互状态 + 动画相位 + 源画布 + 目标画布 + 适配需求版本`。

- 同一状态改变横竖屏，可以有不同目标任务。
- 只改变时间数字、壁纸颜色、相邻动画帧，不自动成为新布局任务。
- 设置面板打开、组件样式变化、抽屉展开，若改变布局结构，应作为独立状态。
- 源/目标必须匹配相同功能状态。`state-001` 这样的编号相同，不构成配对证据。
- 同家族的所有设备、状态、派生图、局部裁剪、扰动和修改版本进入同一个集合。

## 2. 自动事实与人工标签分开

| 层 | 记录内容 | 人工工作 | 是否直接作为主任务答案 |
|---|---|---|---|
| L0 原始证据 | 节点 ID、属性/表达式、资源、运行时框、可见状态、环境、动作轨迹 | 核对图与结构，标出缺失/不支持 | 否；留作追溯和局部定位 |
| L1 组件结构 | 语义组件、父子树、底层成员绑定、刚性/可重排策略 | 确认、拆分、合并组件候选 | 结构理解任务的答案；布局任务的条件 |
| L2 布局意图 | 对齐、顺序、间距、贴边、主体避让、层次与响应式策略 | 说明参照物、强度、来源及何时生效 | 规划/关系任务的答案；明确需求可作为布局条件 |
| L3 目标方案 | 目标布局模式、组框、必要的局部布局、源目标映射 | 人工设计/核验，再渲染复核 | 主布局任务答案 |
| L4 质量反馈 | 问题对象、规则、修正、来源、独立审核 | 记录证据与分歧 | 独立修正/评价任务答案 |

## 3. 怎样划分语义组件

组件定义：**完成一项语义功能，且具有明确共同移动/缩放或内部排布规则的一组对象**。组件树描述所有权，绑定关系描述依赖；不要让同一个叶节点同时归属于两个并列布局组。

判断顺序：

1. 是否承担同一功能，例如时间显示、天气信息、快捷入口、样式设置面板？
2. 是否在状态切换中一起显示、隐藏或移动？
3. 改变目标画布时，成员是否应整体平移/等比缩放？
4. 若成员需要独立移动，是否应成为父组内的子组件？

分组边界规则：

- 小时、分钟、分隔符及其专属阴影可组成时间组；不同数字素材不是不同全局布局决策。
- 日期与天气并非永远绑定；在目标端可能左右分列时必须可作为独立子组件。
- 两个底部快捷按钮可属于同一语义区，但若分别贴左右角，必须保留各自可布局的子组件。
- 整页设置面板是容器，不应为了减少组数，把内部可换列的选项全部冻结为一张大图。
- 装饰属于某组件时跟随该组件；跨组件的前景人物/遮罩保存为独立图层及遮挡关系。
- 多帧动画保存时间轴与共同几何规则；不要把每一帧作为一个布局成员。
- 热区绑定到其视觉组件，分别保留视觉框和点击框。纯热区没有视觉框不是标注错误。
- 一个节点同时显示小时与分钟，允许多个角色；角色与依赖不是单选字符串。

建议每个全局任务先呈现约 **4–12 个可决策组件**；这是操作预算，不是强制标签数。超过预算时按容器和局部任务递归拆分；不能截断剩余元素，也不能为达标乱合并。重要组件清单必须覆盖全部布局责任，其余对象通过成员绑定或明确豁免保留。

每个组件至少填写：稳定 ID、父组、功能角色、成员 ID、源框依据、内部策略、可变换自由度、绑定热区、证据说明。未知为 `null` / `pending`，不能编造。

## 4. 角色、策略与关系

基础角色：`background / foreground_subject / clock / date / weather / status / shortcut / panel / option_list / decoration / other`。`other` 必须附说明；允许角色数组，不按 XML 标签直接赋值。

内部策略：`rigid / row / column / grid / stack / custom`。

- `rigid`：组内成员相对位置固定，整体等比缩放。
- `row/column/grid`：必须保留可重排的子组件及其顺序/间距约束。
- `stack`：描述前后叠层及允许遮挡，不能用“不重叠”一概约束。
- `custom`：写出原因和可执行规则；暂不能执行则进入拓扑变化队列。

关系必须使用稳定对象 ID，至少包含：`type, subject, reference, scope, policy, strength, origin, evidence`。

| 关系 | 必须说明 | 例外处理 |
|---|---|---|
| `center_x / center_y` | 相对画布、安全区、容器或组件；使用几何还是可见框 | 不因视觉接近中心就标为强约束 |
| `attach_left/right/top/bottom` | 参照区、边距及其单位 | 贴角同时记录两个轴 |
| `above / left_of / align_left / align_center_y` | 主体、参照对象及是否保留 | 源关系与目标希望关系分开 |
| `min_gap_x / min_gap_y / equal_gap` | 比较对象、间距范围、单位、框类型 | 不从截图像素间距直接推断设计常量 |
| `same_scale / preserve_aspect` | 同比例对象或单组比例依据 | 目标 xywh 仍需能由执行器实现 |
| `avoid_overlap / allow_overlap / z_before` | 对象、区域、作用层、允许范围 | 人物景深有意叠层必须显式允许 |
| `visual_hit_binding` | 视觉组件和触发区 | 移动视觉组件后热区必须对应更新 |

`policy = preserve / change / optional`；`strength = required / preferred`；`scope = source / target / both`。源图中观察到的关系是 `observed`，不自动成为目标必须保持的关系。需求指定为 `brief`，人工确认来源为 `human`，算法建议为 `algorithm_candidate`。

不要枚举所有组件两两关系。只标影响设计的关系：容器布局规则、关键对齐、相邻组件间距、主体避让、视觉与热区绑定。可由同一容器规则推导的重复关系不重复填写。

## 5. 坐标与视觉证据

全部框为 `xywh`，保留原始像素框并显式声明坐标系：

- 源组件框：相对源完整画布归一化到 1000。
- 目标组框：相对目标安全区归一化到 1000。
- 局部子框：相对父组内容区归一化到 1000，必须记录 `parent_id` 和父区定义。
- 禁止将预览缩略图像素当作脚本坐标；禁止混用分辨率像素和引擎逻辑单位。

表单中的 `canvas`、`coordinate_unit` 与 `safe_region` 共同定义坐标。由现有 `sourceDevice.viewport` 提取的尺寸标为 `engine_logical`，不能仅凭名称当成真实设备物理像素。

对安全区 `(rx, ry, rw, rh)`：`nx=1000*(x-rx)/rw`，`ny=1000*(y-ry)/rh`，`nw=1000*w/rw`，`nh=1000*h/rh`。

四种框分开：脚本求值几何框、实际可见框、热区框、屏内裁剪框。透明 PNG 不能只用图片矩形替代可见框；文字或原生特效无法准确测量时记录未知及原因。

屏外抽屉或过渡组件允许超出 0–1000，但必须有状态证据和屏外策略；普通可见内容不能以此掩盖越界。

壁纸/景深额外记录：主体区域、文字不宜覆盖区、可用留白及遮挡例外。图像无法支持这些判断时挂起，不能从“看起来好看”直接推断标签。

## 6. 目标方案必须补充什么

目标标签需要：目标画布/安全区、适配需求、布局模式、组框/局部框、映射、变换策略、关键关系变化和简短依据。

布局模式词表：`preserve / proportional_scale / reposition / container_reflow / multi_region / topology_change`。不强迫每个样本发生改变；无需修改也是有效设计决定，但必须经审核。

目标来源优先级不是质量评分：

- 原生双形态：核对场景、样式和组件身份，再提取设计目标。
- 设计师人工重排：保存编辑后渲染、可执行框和简短依据。
- 算法或模型候选：始终记录候选来源，人工可以修改或批准，不能伪称原生设计。
- 单张目标生图：仅作参考；若不能对应原素材和执行结构，不能作为可执行布局真值。

多个合理方案用 `alternative_id` 分开保存，合计采样权重不因方案数量无限增加。不要逐坐标平均成一个不存在的“正确布局”。

拓扑变化（拆组、合组、组内换序、新增节点）必须显式记录。当前执行器不能表达的方案标 `requires_topology_support`，不硬塞进根组框 SFT。

## 7. 审核、挂起与版本

状态流：`draft → source_reviewed → target_reviewed → adjudicated → released`，任何阶段可以 `blocked` / `rejected`。

分别记录渲染、分组、关系、状态对应、执行/写回和交互状态。脚本检查通过不等于设计已通过，离线图像完整不等于真机通过。

挂起原因至少支持：`missing_asset / renderer_unsupported / ambiguous_group / ambiguous_pair / missing_design_brief / topology_unsupported / state_mismatch / rights_pending`。

试标期所有任务独立复核；正式批次训练集建议随机双标 20%，高风险和验证/测试样本全部双标。这些比例是项目起点。多人都认可的不同设计方案可并存，结构/状态事实冲突必须仲裁。单人操作时可隔天盲复核，但不能记成独立双标。
