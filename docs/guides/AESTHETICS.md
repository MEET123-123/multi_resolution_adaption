# 布局美学评价与迭代优化

## 研究依据与取舍

| 方法 | 对项目的用途 | 本次实现范围 |
| --- | --- | --- |
| [Ngo / Byrne：界面美学评价](https://eudml.org/doc/207518) | 平衡、对称、密度、节奏等可解释维度 | 使用面向原主题的简化代理；不机械要求所有界面中心对称，不宣称逐式复现全部十四项指标 |
| [LayoutGAN++ / CLG-LO](https://ktrk115.github.io/const_layout/) | 将对齐、重叠和用户关系纳入约束优化 | 独立实现归一化矩形指标和受约束候选搜索；不训练 GAN，不复制其 AGPL 代码 |
| [CGL-GAN](https://arxiv.org/html/2205.00303v3) | 将文字区域背景梯度用于内容相关评价 | 对可读取的主背景生成 Sobel 梯度图，计算文字或图片字形区域的复杂度代理 |
| [LayoutRectifier](https://arxiv.org/html/2508.11177v1) | 离散候选与连续调整交替，减少偏离原布局 | 有界坐标搜索 + Kiwi 可行域投影 + 复评；参考思路，未移植其未发布实现 |
| [WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 区分字号、背景复杂度和真实对比度 | 此轮未实现完整合成画面的前景/背景对比度，不提供 WCAG 合规判定 |

LayoutRectifier 特别指出，全局最近边对齐可能把缺乏视觉关联的元素错误拉到一起。因此这里从原主题推断关联对齐、镜像配对和等间距行，并把原作有意的叠放和不对称作为参考。

## 十个评价维度

| 维度 | 计算方式 | 默认权重 |
| --- | --- | --- |
| 关联对齐 | 原作接近对齐的同角色元素、共同居中元素，在目标中的对应边/中心偏差 | 2 |
| 非预期重叠 | 原作互不相交的组件在目标中的相交面积 / 较小组件面积；弹窗等另行处理 | 3 |
| 视觉重心 | 面积与透明度加权的目标重心相对原作重心的偏差；屏幕中心偏差单独记录 | 1 |
| 原有对称 | 原作中可识别镜像配对在目标中的镜像偏差；没有证据时不启用 | 0.5 |
| 间距节奏 | 原作近似等间距、同角色、同行组件，在目标中的中心间距变异系数 | 1 |
| 密度与留白 | 组件面积和 / 画布面积，与原作密度及 balanced 缩放预期之比的对数偏差 | 0.75 |
| 视觉层级 | 各组件相对原作面积倍率的对数标准差，约束大标题、主体与小控件的相对层级 | 2 |
| 字号大小 | 目标设备像素中的文字字号或图片字形高度，相对源像素大小的缩小程度 | 1.5 |
| 背景复杂度 | 可读主背景上文字/图片字形区域的平均 Sobel 梯度，越平缓越好 | 0.75 |
| 阅读顺序 | 原作同列上下顺序是否反转 | 2 |

各损失映射到 0–1，分数为 `100 × (1 − 有效维度加权平均损失)`。缺失或不适用的维度记录 `available=0`，不把无法评价当作已通过。视觉重心、对称、层级等围绕原作建立目标；不会把全部主题强制排成同一种形式。字体像素大小没有使用设备 PPI、观看距离或实际字面率，是尺寸代理。

## 评价—候选—求解—复评

1. 保存优化前的可行变换；按照相同几何去重评价，但仍对全部缓存状态做硬约束检查。
2. 合并原子组件组、嵌套容器和底部均分链，形成不可拆散的调整单元。
3. 生成小幅横移、纵移及等比缩放候选。默认两轮，最多 48 个候选；后轮步长减半。
4. 使用 Kiwi 将候选投影到可行域：全部稳定资源与热区位于安全区域，原有锚点位置保持，屏外等待内容留在屏外；同一组跨全部状态使用同一后置仿射变换。
5. 拒绝新增非预期叠放、按钮热区遮挡、阅读顺序反转、字号代理退化、占屏倍率扩大超预算，以及任一状态评分降低超过 0.25 的候选。相对于优化前，累计缩放限制在 0.94–1.06。
6. 仅接受整体代理评分改善超过阈值的候选；预算耗尽或没有改善时停止，保留最佳可行结果。
7. 导出前再次检查画布、冻结公共组件、人工 required 约束和原生状态条件。一个人工状态的播放相位共享变换，图片字形倍率不因优化而逐状态改变。
8. 反写 XML、打包 HWT，并进行脚本几何和实时手势验证。

人工分组或人工 required 约束存在时，当前版本只评价，保留人工布局。手动微调锚点的组件不参与自动搜索。新的实时交互仍使用约束布局；缓存外的新场景显示“尚无美学评价”，不伪造分数。

## 使用与扩展

```powershell
.\.venv\Scripts\python.exe .\multires.py tools iterate-aesthetics --workers 3 --candidate-budget 48
```

可用 `--project beihai` 指定项目，`--skip-packages` 仅生成脚本及预览。再次运行从 `scenes/aesthetic-before.json` 的同一基线开始，避免反复缩小。源包或状态集合改变时，用 `--reset-baseline` 建立新基线；旧基线另存。指定项目运行会生成该次运行范围的汇总，不能当作全包验收。

设备或源配置可添加 `adaptation.aesthetics`：`enabled`、`candidateBudget`（0–512）、`rounds`（0–8）、`minGain` 和 `weights`。例如：

```json
{"adaptation":{"aesthetics":{"candidateBudget":96,"rounds":3,"minGain":0.01,"weights":{"hierarchy":3,"balance":0.5}}}}
```

新生成的锚点布局默认进入评价迭代。`layout_scene(...) -> {component_id:{sx,sy,tx,ty}}` 接口保持不变；自有算法可以独立调用 `layout_aesthetics.evaluate(...)` 或 `aesthetic_optimizer.optimize_device(...)`，也可以只借助指标做候选排序。

## 查看结果

- 预览中点击“布局代理评分”查看逐项损失、可评价数量及调整记录；勾选“查看美学优化前”静态对比，原始直板机仍在左侧。
- `theme/adaptation/aesthetic-validation.json`：本次运行的总体结果。
- 本轮真实主题结果与复核项见 [AESTHETICS_RESULTS.md](../reports/AESTHETICS_RESULTS.md)。
- 各项目的 `scenes/aesthetic-report.json`：设备评分、候选预算、接受步骤、拒绝原因。
- 各项目的 `scenes/aesthetic-before.json`：可恢复的优化前变换。
- `theme/adaptation/*/scenes/scripts/` 与 `packages/`：优化后的 XML 和候选 HWT。

这些分数未经设计师偏好数据标定，无法证明主观审美最优。边界检查覆盖可解析、已探索的稳定场景；主背景梯度不等同于完整画面合成、语义显著性、人物/产品遮挡、颜色协调、真实对比度或原生渲染验收。矩形面积也不能替代 PNG 透明轮廓面积。对于分数相近的候选，仍应结合原始与适配预览复核。
