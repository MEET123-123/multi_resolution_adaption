# 主题适配工作台

一个本地页面串联：**上传主题包 → 场景分析与聚类 → 布局策略 → 上传目标参考图 → 组件组匹配 → 生成 XML / HWT**。不需要训练模型。已解析项目也可导入，调整策略和匹配时复用缓存。

## 启动

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe multires.py tools workbench --port 8790
```

打开 `http://127.0.0.1:8790/`。默认工作目录为 `artifacts/workbench/`，只监听 `127.0.0.1`。同一个工作目录只允许一个实例运行。

已有项目可直接加入任务列表，不重新解析主题：

```powershell
.\.venv\Scripts\python.exe multires.py tools workbench --port 8790 `
  --import-project artifacts/learning/real-two-20261020/projects/chusheng/scenes/project.json `
  --import-project artifacts/learning/real-two-20261020/projects/diefeng/scenes/project.json
```

重复导入同一个绝对路径会复用原任务。导入时复制原 HWT 到工作区，复制项目元数据，素材缓存优先使用硬链接（不支持时复制），不修改原项目。导入后的任务不跟随原项目自动更新。

## 使用流程

### 1. 上传与目标配置

选择 HWT / ZIP（最多 100MB），选择 1～4 种目标画布，以及横屏、竖屏。可用画布来自项目已有设备配置，并提供平板模拟、双折叠模拟和自定义分辨率。

双折叠模拟展开宽度为识别出的源宽度的两倍，高度沿用源高度。机型预设是项目配置值，使用时应核对实际设备画布。自定义边长为 240～8192，单画布最多 3200 万像素。

源画布优先由脚本及锁屏预览比例识别；识别不准确时，同时填写源宽和源高。探索默认最多 24 个场景、深度 4，可设置 1～128 个场景、深度 0～8。

上传按字节流落盘，复用已有主题容器检查：路径、嵌套压缩、CRC、展开预算、图片尺寸等。随后后台子进程执行场景探索和布局计算。页面显示上传进度、排队/运行状态及真实日志。

### 2. 场景分析与聚类

页面展示场景数、交互跳转、组件数和设备方向。为每个设备/场景展示：

- 整页重排、公共组件固定后的局部重排、弹窗叠加、布局复用。
- 布局簇、复用来源、组件组数量与冻结数量。
- 居中组、贴边组及约束求解情况。
- 源画布、目标逻辑画布、探索覆盖范围与解释器限制。

点击场景行或选择器可切换预览。分析来自已有交互语义与几何关系推断，属于可审查的规则分析；探索达到上限后的分支不被宣称为全部覆盖。

### 3. 生成布局策略

可选按原关系/锚点排布或按容器排布，以及平衡、随宽、容纳、固定尺寸缩放；可调整缩放系数、居中/贴边推断、已确认组件位置的保留。

点击求解后，从当前版本复制项目并使用缓存的场景重新布局，不重新提取脚本和素材。成功后发布新版本，失败保留已有版本。布局类别仍由场景聚类决定，不把所有交互场景都强制整页重排。

如初次分析的最终 XML 导出遇到无法表达的状态条件，分析与预览仍可保存，并记录警告。后续生成步骤会明确报告编译问题，不发布失败的交付版本。

### 4. 上传目标参考图并匹配

参考图绑定所选设备、方向与已采样场景，要求完整画布、宽高比一致，最多 10MB / 2000 万像素。

支持本地 Qwen3-VL 和原素材模板匹配。生成后展示原素材重渲染、匹配置信度、约束投影、未匹配和回退原因，并可下载建议 JSON。低置信度、缺资源或约束冲突的组保持原位。

切换任务、设备、场景、版本、参考图或匹配参数会使旧建议失效。生成脚本时还会再次校验版本与几何摘要。

模型环境及可插拔匹配接口见 [目标图匹配](TARGET_LAYOUT_MATCHING.md)。默认 Qwen3-VL 仅推理，不加载 mock LoRA，不训练、不上传到第三方。

### 5. 交互预览

页面嵌入已有的原始直板机/适配设备交互预览，也可独立打开。参考图匹配使用工作台上方明确选择的已采样场景。

在预览器中探索出的新实时场景，可使用预览器自身的匹配、应用、导出功能处理。这个 MVP 尚未把预览器内新产生的实时场景自动合并回外层工作台的场景列表。

### 6. 生成脚本与候选包

可以按当前布局直接生成，也可审查后“应用匹配并生成”。默认导出当前设备，可选择全部设备，以及是否同时生成 HWT。

后台在独立版本目录中校验并反写，通过后提供：

- `scripts/<target>.xml`
- `scripts/<target>.patch.json`
- `scripts/<target>.resources.json`
- `packages/<target>.hwt`（勾选生成主题包时）

HWT 为原始包的锁屏脚本/生成资源适配候选；不会自动将全部系统皮肤、主题品类、设备元数据转换成另一设备规范。原生解释器支持、复杂效果、完整设备表现仍以实际验收为准。

历史版本可切换。重新生成布局后，需要重新生成该版本的交付文件。输出会保留原资源身份、变量和交互命令，模型输出只修改几何。

## 数据目录

```text
artifacts/workbench/
├─ workbench.lock
├─ jobs/<任务ID>/
│  ├─ job.json                     任务、配置、当前版本、历史
│  ├─ source.hwt                   上传或导入的原始包
│  └─ <子任务ID>/
│     ├─ task.json / result.json
│     ├─ worker.log
│     └─ output/                   失败时保留现场；成功后移到 projects
└─ projects/<任务ID>-r<版本>/scenes/
   ├─ project.json / assets/
   ├─ preview.html
   ├─ workbench-analysis.json
   ├─ workbench-strategies.json
   ├─ target-matching/<匹配ID>/    参考图、图集、匹配结果和报告
   ├─ scripts/ / packages/
   └─ delivery.json
```

每个工作区最多 100 个主题任务，同时最多 4 个处理任务排队/运行，默认单子进程执行，单步超时 900 秒。可通过 `--timeout 60..3600` 调整。服务重启后，未完成任务记为失败，已发布版本保留；页面可重试首次分析或重新提交策略/生成步骤。

中间文件和历史包不自动清理，大批量使用时按工作区管理空间。可通过 `--root artifacts/workbench-2` 创建独立工作区。

## 扩展入口

| 模块 | 职责 |
|---|---|
| `preview/workbench.py` | 任务、配置、队列、版本、缓存项目导入 |
| `preview/workbench_worker.py` | 后台分析、策略求解、脚本与包生成 |
| `preview/workbench.html` / `workbench_ui.js` | 完整流程界面 |
| `preview/interaction_server.py` | 本地 API、原交互与参考图匹配接口 |
| `pipeline/scene_pipeline.py` | 既有脚本解析、场景项目和原生导出 |
| `preview/target_layout.py` | 匹配器注册、严格协议和几何约束投影 |

布局算法继续使用已有 `SceneLayoutAlgorithm` 接口，可在启动时传 `--algorithm your_module:YourLayoutClass`。这是本地可信操作员配置，网页和主题脚本不能指定任意 Python 模块。默认使用 `anchor`。
