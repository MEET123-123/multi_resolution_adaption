# 左右滑动双场景识别修复

## 本轮范围

主题：`假日特调青柠气泡.hwt`，项目：`theme/adaptation/theme-76e4d14bc5/scenes`。
本轮重新探索和生成这一个主题，其余主题保留既有产物；全局几何汇总合并了未修改项目的历史验证记录。

## 漏掉第二页的原因

1. 初始 `guide=1` 引导层通过 `Trigger action="click"` 关闭。旧手势事务只发出 down/up/tap，没有 click，所以始终停在引导层，旧图只有 1 个状态。
2. 左滑入口在根 Button[2]，条件为 `touch_begin_x-touch_x >= 210`；右滑返回在 Button[3]，条件为位移小于 -210。最后一个全屏 Button[4] 负责纵向解锁。旧命中处理只按层级选择全屏层，横向翻页被纵向解锁层遮挡。
3. 第二页通过 Group 的 `x=#w*(1-#oneSec)` 移到屏外等待。旧媒体首帧逻辑把页切换动画也重置到首帧，再参与普通布局，会使隐藏页提前进入画布。动画帧对 `oneSec1/oneSec2` 的依赖也没有完整传递到原生布局条件。

## 修改

- 点击事务执行原脚本 click 处理器；滑动不产生 click。
- 并存的全屏手势层按脚本中的触摸轴依赖协商方向；保留局部控件捕获、显式 interceptTouch 和严格层级配置。
- 浏览器真实拖动、实时服务和离线探索采用一致的分发规则。
- 动画帧变量纳入依赖分析；触摸期间的临时判定量不再充当稳定场景标识。
- 将具有容器位移和控件显隐证据的用户页切换与媒体播放区分开，布局以页切换的目标态为参考；视频及序列帧仍沿用首帧变换。
- 整页处于屏外时不参与当前页重排；反写保留该页原始坐标，进入该页后应用其目标布局。
- 布局算法插件接口保持现有接口。

## 验证结果

- 识别首页、第二页和首次引导；共 11 个交互状态、151 条手势转移。11 个状态包含音效开关、播放及往返历史参数组合，不能理解为 11 个页面。
- 22 个设备方向、242 个目标状态布局重新生成。22 个设备方向均完成关闭引导 → 左滑第二页 → 右滑首页，原始与适配运行结果一致；起点被局部控件遮挡时改用两侧均可命中的空白区域。
- 触发器采样 18/20，探索未截断。长按相关两个处理器仍未采样，不宣称穷尽交互。
- 本主题对齐检查 550 次、纵向间距关系检查 242 次、严格居中检查 198 次、稳定资源矩形检查 5,566 次，相关失败为 0。
- 22 份 XML 已反写；重新生成平板横屏、双折叠展开竖屏两份候选 HWT。原资源/归档、采样反写几何检查失败为 0，源 HWT 哈希未改变。
- 媒体时间采样几何检查 352 次，失败为 0；未布局的屏外组件及不可用素材另列于媒体报告，不算已验证项。
- 项目回归 183 项通过；25 份现有预览的 JavaScript 语法检查通过。
- 浏览器中实际点击引导关闭按钮，并在平板横屏画布左滑、右滑，已确认两页可往返。
