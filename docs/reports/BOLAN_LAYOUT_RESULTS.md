# 波蓝：底部角落与弹窗缩放修复

本轮只重算 `F:\multi-res\theme\adaptation\theme-04f8e12606\scenes`，保留原来的 96 个交互采样状态，覆盖 22 个设备方向、2,112 个目标布局。原始 `波蓝.hwt` 未修改，旧适配结果保存在 `scenes-before-corner-panel-fix`。

## 原因

1. 左右按钮在多层亮暗样式分组内，外层还有入场位移动画。旧拆分规则跳过了带动画的父分组，将整条底部区域居中缩放，按钮因此向中间收拢。
2. 设置界面没有被识别为弹窗。时间等公共组件固定后，它被当作普通新增内容塞进剩余空间，单独缩得很小。
3. 部分样式中，弹窗边缘恰好与角落图标边缘对齐。若把这项跨区域的巧合当成硬对齐，会与“弹窗居中、按钮固定两角、资源统一缩放”冲突。
4. 拆分后保留下来的父层入场动画也需要同步缩放其位移。只修改子图片坐标，会出现预览与导出脚本的动画距离不一致。

## 修改

- 根据实际图标和点击框的屏幕坐标，穿过样式分组分别归入左下、右下组件；保留原 XML 层级、事件和入场动画。
- 140/148 像素的图标变体以稳定的 148 像素点击框为参考，保留图标在点击框内的偏移。隐藏变体从原脚本求值，不按素材名猜位置。
- 左右边距、底边距与资源等比缩放，图片与点击区域使用相同变换。
- 识别首次隐藏、居中、有面板图片及多个控件的设置弹窗。时间、弹窗与角落控件按设备使用同一资源尺度，提前为弹窗预留整页空间；打开弹窗时无需再次压缩弹窗或移动时间。
- 保留同一区域的对齐与原有上下分离关系；独立角落控件与上方弹窗不因偶然同边而强制横向绑定。
- 同一父层下拆出的组件尺度一致时，同步缩放父层 PositionAnimation 的坐标，保留关键帧时间与原缓动字段。
- 清理旧缓存中的 `ap`、`ut` 触摸临时布局条件；已确认清理前后原生场景的分区一致。
- 自定义布局算法接口保持原样，切换算法时清除本算法的共享尺度约束。

## 比例对比

以下为相对原始资源的统一缩放倍数，不是像素尺寸。

| 设备方向 | 时间：修复前 → 后 | 弹窗：修复前 → 后 |
|---|---:|---:|
| 平板横屏 | 0.463 → 0.313 | 0.175 → 0.313 |
| 双折叠展开竖屏 | 0.717 → 0.556 | 0.374 → 0.556 |
| Mate XT 单屏竖屏 | 1.000 → 1.000 | 0.748 → 1.000 |

平板横屏弹窗的宽高约为原适配结果的 **1.78 倍**。该方向的时间也相应缩小，以保留整页边界和上下间距。左右角落点击框的侧边距约为 26.90 逻辑像素、底边距约为 31.90 逻辑像素；图标保留原来的框内位置。

## 验证

- 22 个设备方向均完成原始/适配两侧的弹窗打开、关闭操作，结果一致。
- 共享尺度检查 8,096 次，失败 0。
- 稳定角落位置检查 4,180 次、边距检查 8,360 次，失败 0；隐藏样式、原有入场及底部布局模式变化另列排除项。
- 画布内资源矩形检查 87,120 次，越界 0。
- 对齐检查 4,004 次、容器内部对齐 44 次，失败 0。
- 横向分离关系 2,134 次、纵向关系 9,592 次、严格居中 2,464 次，失败 0。
- 两个代表设备的媒体/入场时间采样几何检查 700 次，失败 0。
- 两份候选 HWT 的普通元素采样 226 次、字形采样 30 次、新增资源检查 198 次及归档条目检查 1,230 次，失败 0。
- 项目回归 185 项通过，25 份现有预览的 JavaScript 语法检查通过。
- 浏览器平板横屏预览中实际下滑打开弹窗、点击关闭，并确认左右按钮位置。

以上是本地解释器、几何和浏览器验证，未进行原生设备安装验收。96 个采样状态仍有未探索分支，本轮没有宣称穷尽主题交互。其他主题未重新探索或重排；全局报告合并了未修改项目的历史记录，并复核了现有五个角落主题项目。
