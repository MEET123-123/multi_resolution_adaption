# 执行摘要：团队需要形成的共识

业务目标是将一套包含 XML、图层、资源、触发器、变量与动画的主题，自动转换到不同尺寸和屏幕比例，并保证多个交互状态下布局与脚本均有效。这个问题同时涉及软件工程、几何优化、设计生成、计算机视觉与自动化测试。

# 1. 研究边界与问题分解

## 1.1 主题适配不是普通的响应式网页

与常规 App 页面不同，锁屏主题往往存在艺术性构图、复杂叠层、时间/天气等系统变量、滑动及长按触发器、动画与不透明图像资源。适配结果必须写回具体主题引擎支持的属性与语义；ArkUI 的 Grid/Row/Flex 思想可借鉴，但不应假定能够直接写入主题 XML。

## 1.2 五个相互依赖的子问题

| **子问题**            | **输入与输出**                                  | **主要风险**                     |
|-----------------------|-------------------------------------------------|----------------------------------|
| **A. 脚本解析与写回** | 原主题 XML、资源、变量 → 状态机与可回写结构     | 资源 ID、层级、动作语义发生变化  |
| **B. 交互状态抽取**   | 触发器/变量 → 可复现的状态路径与渲染帧          | 嵌套触发、组合爆炸、未覆盖分支   |
| **C. 语义分组与适配** | 原图 + bbox + 层级 + 目标设备 → 新的分组和 xywh | 过分割/合并、共同组件漂移、遮挡  |
| **D. 渲染与评分**     | 目标 HWT 或仿真包 → 多状态截图、差异报告        | 浏览器显示与真机实现不一致       |
| **E. 数据资产**       | 源/目标对应、权利声明、人工标注 → 训练/测试集合 | 弱合成结果被误认为真值、数据泄漏 |

## 1.3 建议明确的“不做”边界

- 阶段一严格约束输出字段：xywh、允许的系统变量及明确批准的规则字段；不随意修改事件触发逻辑与资源语义。

- 不将单张预览截图中的商城按钮、状态栏、动态效果说明识别为主题原生组件。

- 不以任何通用 GUI 基准的高分，直接宣称 HWT 适配成功。

- 不使用 100 套预览素材的程序化扩展结果直接替代设计师配对真值。

# 3. 重点论文研读卡

## 3.1 Phone-to-TV：跨设备规则迁移

论文能力：利用真实手机/电视 GUI 配对，总结分组、归类、转换、动态布局及代码生成规则。

适配切入点：对手机到平板/折叠横屏，优先预测“保留原层 / 整组移动 / 重新排列 / 背景扩展”类型。

限制与风险：TV 交互与锁屏触发语义不同；并不能推出所有艺术元素的最佳布局。

最小验证：选取 15 套复杂主题对比等比例缩放、规则换列与参考样例迁移。

参阅文献 \[R02\]

## 3.2 ORC Layout：硬/软约束和候选结构

论文能力：使用 OR-Constraints 将栅格、流式与条件布局放入同一约束体系，可在不同宽高比重排。

适配切入点：将锚点、固定组、相对间距、避让区、最低字号编码为机器可审的硬性约束。

限制与风险：部分审美表达不可通过线性约束完整表示；违反规则的“艺术性重叠”需人工标注。

最小验证：建立条件布局 DSL，对单/双列切换与锁定时钟做 6 种设备回归。

参阅文献 \[R03\]

## 3.3 UISCGD / UIED：图层与元素识别

论文能力：先检测 UI 元素，再用语义分组网络识别功能关联或视觉关联。

适配切入点：先用 XML 父子关系、共享变量和运动一致性构图，再用视觉模型纠正过分割/过合并。

限制与风险：以一般 UI 图标和文本为主的模型，可能误判大幅艺术贴图、遮挡与透明装饰。

最小验证：人工标注 50–100 个组件组，测 Purity/组级 F1 与跨状态一致性。

参阅文献 \[R04\]\[R05\]

## 3.4 RALF：检索增强布局

论文能力：根据输入图像查找邻近设计实例，再把检索结果馈送给自回归布局模型。

适配切入点：按主题构图、目标宽高比、元素组成及空间密度检索“成功适配参考”，提示 LLM 生成 xywh。

限制与风险：需要真实优质候选库；相似图片不一定对应相似布局规则。

最小验证：比较零样本 LLM、检索 top-3+LLM，以及简单约束式换列，固定同一评测集。

参阅文献 \[R08\]

## 3.5 BLT / LayoutDM：可控细化

论文能力：BLT 通过掩码属性预测迭代修复低置信度布局；离散 LayoutDM 可在推理时施加部分类型/位置约束。

适配切入点：全局布局大致正确时，只优化失败组；公共组件与已验收元素保持不动。

限制与风险：模型训练需更大规模的高质量结构标签；成本明显高于 prompt + 规则。

最小验证：暂以方法论对照，不先训练；数据积累后评估 group-level 编辑与锁定能力。

参阅文献 \[R09\]\[R10\]

## 3.6 UI2Codeᴺ / UICoder：真实反馈

论文能力：前者用执行后视觉反馈形成迭代优化，后者强调编译器与多模态评估筛选合成数据。

适配切入点：主题修改 → 浏览器/Theme Studio 预览 → 静态和视觉质检 → 失败组重写；迭代最多三轮。

限制与风险：Web UI 的执行结果不代表 HarmonyOS 原生主题效果；自动视觉评分也可能偏差。

最小验证：在同一 20 套集上比较 0、1、3 次反馈后的结构通过率和人工喜好分数。

参阅文献 \[R14\]\[R15\]

## 3.7 DroidBot / Nighthawk：状态探索与显示缺陷

论文能力：用状态图抽取测试序列，并从截图中检测或定位显示失败；无 Oracle 方法关注跨视口关系。

适配切入点：使用真实触发命令驱动场景探索，静态差异 + 组件关系 + 视觉模型定位问题。

限制与风险：Android 的 View Hierarchy 不等于 HWT；单纯 screenshot diff 容易误判动画。

最小验证：构建 P0 基准、P1 互斥、P2 风险组合、P3 固定时电、P4 动画过渡分层回放。

参阅文献 \[R16\]\[R18\]\[R19\]

## 3.8 SAM 2 / LaMa：前景与背景资产

论文能力：SAM 2 提供可提示图/视频对象分割，LaMa 解决较大掩码的背景修补问题。

适配切入点：对源背景、主体及装饰候选图层做资产工程，为横屏延展提供素材。

限制与风险：“抠得像”与“抠得语义正确”不同，修补背景也不一定是设计师原图。

最小验证：仅纳入 alpha 边缘质量、主体完整率、扩图真实性通过人审的结果。

参阅文献 \[R21\]\[R22\]

# 4. 华为主题规范与工程边界

华为主题引擎的规范版本、设备类型和根标签能力是第一层事实来源。HarmonyOS 应用响应式布局、浏览器 CSS 布局及主题引擎 XML 是不同系统，不能用论文或 ArkUI 示例替代主题引擎兼容性检查。

| **官方资料**                                  | **当前可核实事实**                                                                                                     | **工程动作**                                                        |
|-----------------------------------------------|------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------|
| **Button / Trigger（HarmonyOS 5.0+）\[H01\]** | 锁屏 Button 支持直板、折叠、平板；文档列出 down/up/double/click/long/pause/resume 等具体行为，个别事件有更晚版本门槛。 | 按规范版本解析 action 白名单和热区，另行验证 Slider/Unlocker 语义。 |
| **VariableAnimation \[H02\]**                 | 锁屏及直板/折叠/平板在对应新引擎规范中有支持范围；变量动画有时序语义。                                                 | 状态回放不仅比较变量最终值，还要检查动画时间/暂停恢复。             |
| **Theme Studio \[H03\]**                      | 官方提供实时预览、资源规范校验与手机同步检验能力。                                                                     | 通过 Studio/真机作为最终证据层；仿真器结果单独标注。                |

## 4.1 推荐建立版本能力矩阵

字段建议：engineVersion、rootTag、deviceType、elementTag、supportedAttrs、triggerActions、variableSemantics、animationTags、knownLimitations、verifiedBy。对“未知”应 fail closed，不可默认可写。

## 4.2 XML 写回的硬边界

- 保持原始元素 ID、脚本层级与依赖关系；仅修改被允许的坐标/尺寸/系统参数。

- 将 hitbox 视为交互元素，随显示元素更新，不能只调整视觉图片。

- 跨状态公共组件应有固定或受限可移动的约束，不允许每帧随机漂移。

- 静态截图通过 ≠ 动画相位验证通过 ≠ 华为真机已验证。

## 5.1 一条可回溯的训练/评测样本应该包含

## 5.2 推理输出的最低契约

输出应是版本化的 JSON Patch（只表达实际改变的组或元素），并包含变更原因、约束违反列表和 expectedSceneIds。建议记录每一轮输入 prompt、模型版本、采样参数、布局差异与截图路径，便于回滚和消融实验。

# 6. 核心实验设计与评测体系

## 6.1 先做三个对比实验

| **实验**         | **对照组**                     | **实验组**                    | **主要观察指标**                       |
|------------------|--------------------------------|-------------------------------|----------------------------------------|
| **E1：跨屏布局** | 等比缩放 / 居中裁剪 / 人工规则 | 检索增强 LLM + 硬约束         | 有效布局率、主体占比、越界、设计师偏好 |
| **E2：组件分组** | 原 XML 父子关系                | XML + 视觉分组 + 跨状态一致性 | 组级 F1、过合并率、过分割率            |
| **E3：反馈迭代** | 只生成一次                     | 渲染反馈 1 次 / 最多 3 次     | 质量增益、平均修复次数、回归退化率     |

## 6.2 评价指标分层

| **层级**          | **指标**                                  | **判定方法**                  |
|-------------------|-------------------------------------------|-------------------------------|
| **L0 脚本必过**   | XML 可解析、依赖齐全、引擎字段兼容        | 确定性校验器；失败即拒绝      |
| **L1 元素几何**   | inside、aspect、min_size、组件相对位置    | 布局 JSON 与渲染后的实际 bbox |
| **L2 跨状态**     | 公共组件方差、错误跳转率、hitbox 一致性   | 状态回放、多帧互斥变量对比    |
| **L3 视觉**       | 主体占比/重心、留白、风格保持、文字清晰度 | CV 特征 + 多模态 + 人工双评   |
| **L4 原生可用性** | 真机运行、实际手势、动画相位与兼容性      | Theme Studio + 原生设备实测   |

项目可把质量门禁设计为：L0/L1 的关键硬性规则必须全部通过；L2 的测试覆盖记录达到约定目标；L3 按人工校准的阈值与设计师复核；L4 只用于正式交付前认证。阈值必须通过真实样例统计获得，而不能把本文建议值写作论文实测结论。

## 6.3 数据规模与评测集约束

- 先用 10 套主题贯通解析、状态回放、目标预览、回写和错误图；再用 ≥30 套覆盖不同视觉风格与复杂交互（仅作为建议起点）。

- 评测集按“主题包”隔离；同一主题的不同截图、状态、目标尺寸、裁剪和近重复资源必须处于同一划分。

- 人工多设备配对优于基于商店预览的规则合成。合成数据仍保留 weak_synthetic 标识，不自动批准入训。

- 必须区分原始 HWT/XML、主题预览图、商店产品图、系统界面截图、浏览器仿真截图等来源。

# 7. 数据治理：如何避免“更多但不能用”的样本

数据供给本身可能决定模型上限。检索增强可以缓解小样本问题，但只有可靠“成功适配参考”才能迁移布局；图像分割 + 背景修复不会自动产生真实多设备对应关系。

| **数据类型**                  | **能做什么**                             | **绝对不能宣称**                   |
|-------------------------------|------------------------------------------|------------------------------------|
| **真实主题 + 设计师多设备包** | 评测和监督核心；支持锚点、群组、遮挡分析 | 未经匹配验证的跨主题对应是正确配对 |
| **单主题多个交互帧**          | 状态分类、触发可达性与一致性评测         | 左右滑截图可以逆推出完整触发器     |
| **第三方预览 / 商店展示图**   | 风格聚类、可视语义、优质版式检索         | 展示图中的商城 UI 是锁屏元素       |
| **抠图/扩图/程序化重绘**      | 辅助资产、算法稳健性测试、预训练候选     | 程序合成目标即设计师认可的目标图   |
| **LLM/多模态模型改图**        | 生成假设与候选答案                       | 未经渲染/人审可以直接当真值        |

## 7.1 三段数据门禁

1.  来源与合规：检查授权、来源 URL、主题包 ID、原始哈希、素材可用范围与去重。

2.  语义与结构：检查源/目标对应、主题隔离、xmlID 保持、bbox 与图层分割质量。

3.  质量与可用：浏览器预览、多状态回放、必要人工复核、原生主题验收状态。

## 7.2 已有预览实验的定位（仅作为项目背景）

此前有一批主题商店预览素材参与的内部实验，已做过“原图裁剪/模糊补边”的 v1 生成和“程序化图层重排”的 v2 候选探索。这可以验证渲染、数据协议和几何质量门禁，但由于缺少可靠的原生主题 XML、人工标注的多设备目标与明确的素材授权，暂不能当作真实 HWT 自动适配的监督真值。

# 8. 工程路线与阶段里程碑

## 8.1 三条方案及取舍

| **路线**           | **能力边界**                       | **建议阶段**      | **判断退出条件**                           |
|--------------------|------------------------------------|-------------------|--------------------------------------------|
| **A 约束/规则**    | 稳健且可解释；复杂艺术布局处理有限 | P0 基线，始终保留 | 跨屏结构通过率达到可靠基线；为所有模型兜底 |
| **B 检索 + LLM**   | 易接入，响应快；坐标与遮挡不稳定   | P0 主线           | 在盲测集上明显优于 A，且失败可定向修复     |
| **C 微调布局模型** | 适合规模化但依赖真实配对           | P2 后考虑         | 达到足量高质量配对/明确统计收益再投入      |

## 8.2 建议六周研究安排（可按团队资源调整）

| **周次** | **核心任务**                                | **负责人建议**     | **交付物**                        |
|----------|---------------------------------------------|--------------------|-----------------------------------|
| **W1**   | 文献共读 + 规范版本矩阵 + 10 包样本盘点     | 算法 + 客户端      | 证据清单 / 风险列表 / 基准选择    |
| **W2**   | 状态机抽取与多帧回放；锁定资源/变量约束     | 脚本/后端 + 测试   | 状态路径 JSON / 回放报告          |
| **W3**   | 分组与布局 DSL，规则 baseline，六设备可视化 | 算法 + 前端        | 可复现实验 E1-A / 错误图          |
| **W4**   | 检索增强 LLM 输出 xywh 及差量 JSON          | 算法 + 前端        | E1-B 与消融实验记录               |
| **W5**   | 反馈迭代和结构/视觉评分，比较 0/1/3 次      | 算法 + 测试 + 设计 | E2/E3 汇总与失败归因              |
| **W6**   | 人工复核盲评 + 原生真机小批验证 + 方案决策  | 设计 + 测试 + PM   | 评审报告 / 是否扩大数据规模的决策 |

## 8.3 分工接口

- 算法：结构化 Prompt、检索、分组、约束求解、质量评分与消融实验。

- 前端：原始/目标场景同步展示、布局差异高亮、失败截图、人工复核入口。

- 后端/工具：HWT/XML 读写、资源索引、状态机调用、批量任务及产物溯源。

- 测试：不同状态、分辨率与引擎规范的自动回归，负责真机证据。

- 设计：组件组标注规范、典型失败分类、盲评和人工真值验收。

- 多少真实主题包、人工适配配对和可回放交互足以开始评估微调投资？
